# T04 Today implementation plan

**Goal:** Replace the existing Today placeholder with a permission-free local daily feed and keep Quick Capture reachable from all primary destinations.

**Architecture:** The shell owns saved date selection and capture-sheet visibility. A small Flow adapter maps the domain repository into loading, empty, data, and error states. Compose collects only while visible; rows and counts derive from stored envelopes, without introducing T14 metrics or T05–T07 capture forms.

**Tech stack:** Existing Kotlin, Compose Material 3, Navigation, Coroutines, Room; Lifecycle Compose for observation.

**Spec:** `TASKS.md` T04 and `ARCHITECTURE.md`.

## Constraints and decisions

- Preserve the user's existing Gradle/SDK changes and generated schema.
- Work in the supplied checkout so the Android Studio project keeps the user's local build configuration. No commits, merge, or push are part of this request.
- Keep Timeline, Review, and Settings as future-task placeholders.
- Quick Capture opens a sheet with clearly labeled upcoming capture types; it writes no incomplete records.
- Local dates use the current system zone. Date-picker values use UTC calendar dates, not local-midnight conversion.
- Refresh the current day/zone on resume and while foregrounded. An explicit date stays selected across navigation and recreation; returning to Today resumes following the current date.
- Run local JVM/build/lint checks if available; do not launch an emulator.

## Review focus

- DST and UTC picker conversion must preserve the calendar date.
- Changing dates must immediately drop rows from the old day.
- Repository failures must permit retry and never expose raw exception contents.
- Live writes must update the displayed event list and counts.
- Recreation and tab switching must retain selection and capture access.

## Execution record

- Baseline Gradle invocation needed `bash gradlew` because the launcher is not executable; the default sandbox cannot write the existing Gradle cache. Local Gradle execution was approved by the automatic reviewer.
- The cancellation test failed against Flow.catch, which can catch a manually thrown CancellationException; explicit cancellation propagation makes all six state tests pass.
- Review found picker initialization outside 1900..2100 and a non-scrollable sheet. The picker range now includes the selected year, with a compiled device regression test; sheet content scrolls. Re-review found no important issues.
- Final JVM tests (19), debug and both instrumentation APK builds, and data lint pass. App lint crashes in Lifecycle/Compose detectors; rules and build-tool versions remain unchanged.
- Deferred device checks: midnight/zone refresh, delayed emissions during switching, and constrained-size/large-font UI. Device testing stays with the user as requested by the task record.
