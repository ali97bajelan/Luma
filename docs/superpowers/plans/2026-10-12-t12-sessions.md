# T12 session views implementation plan

> Use superpowers:executing-plans to execute inline; steps record validation here.

**Goal:** Show recorded app visits and daily totals while excluding unused apps.
**Architecture:** Domain session models and day calculation; Android event
adapter; additive Room session/window storage; saved Settings view selection.
**Tech stack:** Existing Kotlin, Room, Compose, UsageStatsManager; no dependencies.
**Spec:** ../specs/2026-10-12-t12-sessions-design.md

## Constraints and review focus

Preserve API 28/35, existing records and unrelated working changes. Do not commit.
Review multi-activity overlap, missing boundary events, retention loss, ongoing
retry identity, and atomic rollback/opt-out together with migration preservation.

queryUsageStats cannot supply visits. Gradle requires cache writes outside the
sandbox; approved escalation runs the installed offline tooling.

tests initially failed for missing APIs; sync session-only/empty imports failed
before integration. All domain/adapter tests are green, including DST/skipped-day
and same-class overlap/equal-time reopen regressions.

Persistence/UI: nine Room cases first ran with three missing-session failures.
The new view-selector case failed before the UI change. Migration initially failed
because the test-assets copy preceded schema export; task ordering now includes the
current exported schema. Both v1/v2 snapshots are present. Full Room suite: 76 pass.

hiding legacy totals. Both reproduced RED and were corrected; follow-up review
found no remaining Important/Critical issue. Complete-window coverage and saved
selector restoration were added. Native sessions import and retry on real Android
events, four Settings flows and three summary flows all pass (8 focused checks).

Final: 205 JVM tests pass; normal debug/test APK builds and data/usage lint pass.

retry. This is recorded without claiming a clean whole-suite run. No commits made.
