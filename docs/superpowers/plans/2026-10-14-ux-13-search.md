# Visible Search Filters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every structured search filter identifiable and individually removable outside the dialog, with distinct filter reset and whole-query clear.

**Architecture:** Project existing SearchInput and SearchOptions into stable chip descriptors. All mutations go through SearchViewModel's existing saved-input/generation pipeline; the route renders a scrollable filter section above results.

**Tech Stack:** Kotlin, Compose Material 3, SavedStateHandle, coroutines, JUnit 4, Compose instrumentation.

**Spec:** [UX 13 design](../specs/2026-10-14-ux-13-search-design.md).

**Status:** Proposed plan; implementation has not started. Read the [master handoff](../../UX_DEVELOPMENT_READY_2026-10-14.md) and [acceptance checklist](../../UX_ACCEPTANCE_2026-10-14.md).

## Global Constraints

- Keep `minSdk = 28`, `compileSdk = 35`, `targetSdk = 35`, JDK 17, AGP 8.7.3, Kotlin 2.2.10 and Compose BOM 2025.08.01.
- Add no product dependency, database migration, permission, network access, telemetry or AI service.
- Keep English, Persian and French available offline; localize all new labels, dates, numbers and semantic descriptions.
- Preserve user-authored text, stable IDs, raw durations, occurrence timestamps and timezone rules.
- Preserve unsaved-change confirmations, rejected pending-tag save blocking, photo retention, read-only imported records and retry behavior.
- Missing observations stay unavailable; recorded zero stays zero; positive durations never display as zero.
- Every interactive control has an accessible name and at least a 48 dp touch target. Text wraps or ellipsizes without reducing the configured font scale.
- Automated semantics checks do not certify TalkBack speech. Manual acceptance remains pending until evidence is recorded.

## Review Focus

- Deleted/failed-loading catalog selection remains visible and removable by UUID: Task 1 projection + Task 2 UI.
- Same-name selections remain distinct, including repeated stale removal: Task 1 mutation/projection.
- Reset during an uncancellable old request cannot publish old results: Task 1 generation test.
- 203 selected filters at 320 dp/scale 2.0 do not consume a fixed viewport: Task 2 scrolling test.
- Invalid dates can be corrected by removing one endpoint without losing text: Task 1 state + Task 2 flow.
