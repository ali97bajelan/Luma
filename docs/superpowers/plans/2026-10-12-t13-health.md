# T13 Health Connect Steps Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline. Steps use checkboxes for tracking.

**Goal:** Import real Health Connect steps with optional access and idempotent local storage.

**Architecture:** Pure domain sync contracts, a Health Connect adapter, transactional Room storage and a Settings card. Reuse existing activity browsing and summaries.

**Tech Stack:** Kotlin, coroutines, Room, Compose, AndroidX Health Connect 1.1.0-beta01.

**Spec:** `docs/superpowers/specs/2026-10-12-t13-health-design.md`

## Global Constraints

- Database version 1, min API 28, compile/target API 35.
- READ_STEPS only; foreground imports; seven calendar dates in a durable import zone.
- Null is unavailable; zero is known; failed reads preserve records and checkpoint.
- User release artifacts and generated schema are pre-existing and remain untouched.

## Review Focus

- Timezone changes must retain a single set of aggregate intervals.
- Provider deletes/edits must update or remove the same daily record.
- Opt-out during slow reads must prevent late commits.
- Missing or revoked providers must leave manual capture/navigation available.
- Invalid/conflicting batch input must roll back both data and sync state.
