# WD09 and WD10 Widget UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Record a reproducible widget baseline and implement the WD10 header and metadata hierarchy with measured, localized layout behavior.

**Architecture:** Use fictional `WidgetSnapshot` fixtures through the existing `WidgetRenderer` and retain the baseline report and rendered captures as evidence. Keep RemoteViews providers and stored actions; update the shared regular/stacked shell, renderer measurement, semantic palette resources and localized strings without changing the widget data contract.

**Tech Stack:** Kotlin, Android RemoteViews, Android instrumentation, XML resources, Gradle.

**Spec:** [Widget visual review](../../WIDGET_VISUAL_REVIEW_2026-10-20.md), tasks WD09 and WD10.

## Global Constraints

- Keep existing providers, intent destinations, per-instance privacy and persisted action tokens.
- Use fictional fixtures only; do not read or mutate personal records.
- Preserve explicit dates, tracking-zone information and old-snapshot wording.
- Header targets remain at least 48dp; keep 8dp between adjacent header targets.
- Do not expose a “Scroll for more” hint until WD17 makes the collection scrollable.
- Do not claim device acceptance if the required isolated emulator is unavailable.
- Work in the supplied checkout to preserve the current task-status edit and leave existing untracked APK/evidence artifacts untouched.
- Do not create a commit; provide a generated commit message for the user.

## Review Focus

- Large translated title/count labels at 100%, 130% and 200% text scale must stack or omit only the optional count without clipping required actions.
- A data count cue must represent the full eligible total, never visible rows or a static omitted prefix.
- An old snapshot must identify both the snapshot date and successful update date/time, with its tracking zone when it differs from the device zone.
- A successful freshness label must appear before feedback and rows, and only once.
- Focused and pressed states must remain visibly distinct while foreground/background contrast meets the documented thresholds.
