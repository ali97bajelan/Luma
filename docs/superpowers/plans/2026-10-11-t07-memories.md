# T07 Memories implementation plan

> Use superpowers:executing-plans to implement this plan inline.

**Goal:** Capture direct memories and reversibly mark eligible existing records without copying content; browse memory status on timeline and in review.

**Architecture:** Extend LifeEventRecord with optional MemoryDetails. Existing v1 memory rows serve both standalone MEMORY events and markers on complete manual MOOD/JOURNAL events. Targeted transactions preserve original events, details, links and marker IDs. Navigation-scoped SavedStateHandle drafts follow journal recovery patterns with bounded text.

**Tech Stack:** Existing Kotlin, Room, Flow, Compose and JUnit; no new dependencies.

**Spec:** TASKS.md T07 and ARCHITECTURE.md.

## Constraints
- No migration, network, runtime permission, duplicated journal/mood content or future statistics.
- Direct capture requires note text; optional title, importance 1–5, and timestamp. Title <=200 and note <=10,000 characters; reject oversized draft changes visibly and retain previous text.
- Promotion/edit marker supports complete manual mood and journal records. Original title/content/time is read-only; marker note and importance are optional.
- Unmarking preserves the event and every unrelated link; standalone deletion confirms and rejects media references pending T10.
- Review lists memories in the current ISO calendar week in the system zone, without T16 metrics.

## Review focus
- Retry/recreation after an ambiguous create, marker save, unmark or delete must reconcile committed state.
- Missing, incomplete, imported and unsupported records must reject protected writes.
- Promoting/editing/unmarking preserves event/child IDs, body, tags, people, places, attachments and metadata.
- Editing source mood/journal preserves the memory marker; derived summaries become stale atomically.
- Changed drafts survive navigation/recreation/error; oversized text cannot enter saved state.
