# T14 Daily summaries design

Implement explicitly requested TASKS.md T14, leaving T13 pending. Daily summaries describe saved records, not complete provider coverage or inferred behavior. Preserve the current uncommitted T12 implementation, schema exports and earlier plans. Work in the shared checkout without commits, device execution or dependency/SDK/schema changes.

Architecture: pure domain SummaryRecord snapshots, DailySummary values and deterministic calculateDailySummary(date, zone, records); DailySummaryRepository observation/get/recalculate contracts; RoomDailySummaryRepository implementing the existing v1 daily_summary cache; Today displays a separate summary card with independent loading/error/retry. Existing Today event browsing remains usable if summary loading fails. app wires the repository through LumaStorage.

Metrics: distinct stored events by occurrence date in the requested zone; known journal and memory-marker counts (promotions count once in total records and once as a memory); mood score averages and optional energy/stress averages stored as exact sums/sample counts; foreground usage using native bucket starts and stored millisecond totals, with app/package labels; activity totals grouped by exact type/unit/source, summed as BigDecimal from stored finite nonnegative doubles. Unknown/incomplete typed envelopes count as records but do not invent typed observations. Missing moods, usage or activity are nullable/unavailable; actual recorded zero usage/activity remains zero. Manual counts of zero describe the absence of saved entries, not a measured signal.

Day semantics: manual/mood/journal/memory/activity metrics use half-open local-midnight occurrence bounds, including DST and skipped civil days. Usage follows native bucket-start dates as in T12, with no clipping/proration or device screen-on claim. Query both indexed event occurrence and native usage starts so imported parent timestamps cannot hide eligible buckets. Deduplicate identical event snapshots; reject conflicting snapshots, activity identities or native usage observations. Canonical package/group ordering and exact numeric sums make results independent of row order.

Cache: existing date+zone primary key, algorithm version 1 plus a format marker in metrics_json, computed timestamp and freshness. Cache only derived counts/sums/totals/labels, never private journal/memory body text. Validate decoded data; stale, old-version, incompatible or corrupt cache falls back to raw recalculation. Read source projections and upsert within one Room transaction; errors do not replace a cache with fabricated zero. Application writers already mark derived rows stale atomically. Reactive observation watches raw dependency tables, not cache writes, and recomputes after source changes without a self-triggering write loop. Collection restarts use source recomputation to recover from stopped-screen changes. Forced recalculation and deletion/rebuild must produce equal metrics. No integration permission/status is assumed to prove a known zero.

UI: a Saved daily summary card on Today for empty and populated days, exposing counts, mood/energy/stress averages with sample counts, foreground usage total/app rows, activity type/unit/provider totals, and explicit unavailable states. Localized number formatting; labels explain saved-only coverage and native interval/clock incompleteness. Existing event routes and navigation remain. Errors expose retry independently of the feed. No charts, weekly comparisons, search, causal claims, health acquisition or new services.

Alternatives: derive solely from Today rows (simple but cannot provide a reusable/versioned cache or find usage by native starts); SQL-only aggregates (compact but moves numerical/day rules out of the tested domain); selected approach keeps reproducible rules in Kotlin with atomic Room caching.

Validation: domain and UI JVM regressions first; Room and Compose fixtures compile only because device execution remains pending. Run all JVM suites, debug and both instrumentation APKs, data/adapter lint and an app lint attempt (known bundled analyzer compatibility failure). One independent read-only final review. Document results, explicit T13 omission, cache/raw-day semantics and a T14 commit message.
