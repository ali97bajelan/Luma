# UX review follow-up: findings 08, 09 and 15

Status: design approved by the user; written spec awaiting user review.

## Intent and scope

Address three findings in docs/UX_REVIEW_2026-10-13.md:

- 08: make Weekly Review useful as an overview before asking the user to scan
  comparison and evidence cards.
- 09: make Settings a configuration hub and give saved usage browsing a clear
  route outside Settings.
- 15: make Places as discoverable as People and show the entries linked to a
  place, matching the useful history already available for a person.

Keep the existing five primary destinations, local-only data model, capture
flows, permissions, language support, and weekly report calculations. Do not
change the meaning of saved measurements, infer causes, add AI or network
services, or introduce a database migration. Place history is derived from the
existing event-place links.

## User experience

### Weekly Review overview

Keep the existing week selector, comparison dates, date picker, and selected
week restoration. Reorder the content so the first screenful introduces the
selected week and its saved observations, then shows a compact overview before
the detailed evidence.

The overview presents:

- mood as the existing sample-weighted average, including its sample count or
  an explicit unavailable state;
- the most recent saved memory in the selected period, with its date and the
  existing event action; this is a convenient example, not an inferred
  measure of importance;
- current-period saved screen-time total and a concise coverage state;
- the current activity metric with the largest sample count, labeled as the
  most-sampled metric and showing its unit and sample count; ties use a stable
  type, unit and source order. Values with unlike units are never compared;
- a compact people/places observation that continues to describe linked
  records, not time spent together or visits.

Add accessible section navigation for Mood, Memories, People/Places, Usage,
and Activity. Selecting a section scrolls its heading into view without
changing the selected week. Keep full comparisons and source navigation in
those sections. Replace the repeated current/previous source buttons on each
metric with one compact Sources control that offers the current and previous
period actions when both are available; a single available period remains a
direct action.

Keep the saved-observation explanation, timezone, partial-week label, and
missing-versus-zero distinctions visible in the overview context. Put the
long methodology explanation, detailed usage coverage, and per-day evidence
behind clearly named disclosures within their relevant sections. The saved
usage day view remains read-only and is reachable from the Review usage
section. Preserve retry, loading, empty states, bounded source pages, and
existing memory/event actions.

Do not generate a narrative or rank memories by inferred sentiment. The
overview's latest memory is chosen only by event time. The activity summary
uses sample count rather than comparing unlike values. At larger text sizes,
all content wraps or scrolls; section controls remain operable and named.

### Settings hub

Replace the mixed Settings feed with a short hub of clearly labeled rows:
Language, Backup, Privacy, and Integrations. Each available row opens a
focused screen. Show only destinations supported by the services supplied to
the app; Language is always available. Keep Backup and Privacy safeguards and
all existing explanatory copy and state behavior.

The Integrations screen contains current screen-time and health configuration,
including enabled state, access status, import/refresh controls, retention
explanations, and retries. It contains no day-by-day saved usage report.

Remove day navigation and the usage timeline/totals feed from Settings. Keep
saved usage available through Weekly Review's Usage section and its existing
read-only per-day screen. The Timeline continues to show usage entries under
its existing visibility preference. The daily usage view must not request
provider access or start an import.

Secondary Settings pages hide the primary bottom navigation, provide a clear
Back action, and preserve existing route behavior. Returning from a focused
page returns to the Settings hub. If a service is absent, its row and route
are absent rather than showing an unusable empty page.

### People and Places catalog

Keep the People primary destination and add an accessible People/Places
selector at the top of its catalog screen. Each selection shows the existing
list, empty state, retry behavior, and create action for that catalog. Opening
a place retains the existing detail and edit flow.

Add linked-entry history to place details. Add a PlaceHistory domain snapshot
and a PlaceRepository observation that emits the place and its linked event
records together, or null when the place has been deleted. Implement it with
the existing event-place relationship so updates to a place link or event
refresh the detail. History is chronological, displayed oldest first in a lazy
list, and each entry opens through the existing event callback. Empty,
loading, missing, and retry states match the current person/place patterns.
Deleting a place continues to remove catalog links only and never deletes
event content.

The catalog selector is state local to the People destination and survives
ordinary recomposition and navigation restoration. Place creation from the
catalog continues through the existing editor and returns to the Places
selection after saving or canceling.

## Navigation and data flow

The five bottom destinations remain Today, Timeline, People, Review and
Settings. Settings hub rows navigate to focused child routes. Existing
Review-to-usage navigation remains the deliberate saved-usage entry. The
People destination owns the catalog selector and routes place details to the
existing place destination.

Place detail observes PlaceRepository history. The repository exposes a
committed snapshot using the existing Room event-place relation and typed
event mapping. No event or catalog table changes are needed. Existing
person-history behavior is unchanged.

Weekly report calculations and repository contracts remain unchanged. The
overview formats only values already present in WeeklyReview and the bounded
memory source page. Missing measurements remain unavailable; known zero stays
zero; partial coverage is explicit. The latest memory is obtained from the
existing ascending, paged source query by requesting the last matching row.
The activity overview chooses by sample count and stable tie-breaks, never by
comparing values across units or sources.

## Localization and accessibility

Add user-facing labels and explanations to English, Persian and French
resources. Use localized number/date/duration formatting already used by the
app. Verify the catalog selector, Settings rows, Review section controls,
Sources menu and disclosures in both left-to-right and right-to-left layouts.
Controls expose names, selected/expanded state and appropriate roles. Source
and history rows remain reachable by keyboard and TalkBack.

## Acceptance criteria

1. Review opens with a concise week overview. A user can reach mood, a saved
   memory, saved screen-time and a recorded activity result from the overview
   or section navigation without scanning all detailed evidence cards.
2. Week navigation and restoration, partial-week labels, saved-observation
   context, current/previous values, source identity, missing-versus-zero,
   and read-only per-day usage navigation continue to work.
3. Long methodology, usage coverage and daily evidence are available on
   request. Review content remains usable with larger text and Persian RTL.
4. Settings shows only focused configuration destinations. Language, Backup,
   Privacy and Integrations are directly identifiable; the day-based usage
   feed is not part of Settings.
5. A user can reach saved usage from Review. Its daily view remains read-only
   and does not request permission or import data.
6. People and Places are equally discoverable from the existing primary
   destination. Both catalog selections support their current create, empty,
   loading, error and retry flows.
7. A place detail displays its linked events in chronological order and opens
   them through the existing event action. Link/event changes update observed
   history; place deletion retains event content.
8. All new UI copy is localized in English, Persian and French, with usable
   RTL layout and accessible labels and state.

## Verification plan

Use focused domain/state and Room coverage for latest-memory paging, stable
activity selection, place history updates, chronological order, missing-place
emission, and deletion retaining events. Compose/navigation coverage should
exercise Review section navigation and source actions, Settings hub routes and
usage separation, catalog switching/restoration, place creation return, and
place history event opening. Inspect English, Persian RTL, French, and larger
text layouts in the running app where the environment permits. Record any
device-only checks that cannot be executed. Preserve all pre-existing
untracked files and do not change unrelated review findings.
