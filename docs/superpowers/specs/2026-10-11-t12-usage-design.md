# T12 Screen-time integration design

Intent: implement TASKS.md T12 using native Android reported foreground usage, optional special access, retryable/idempotent imports, package labels and daily totals. Core records remain usable without access. No health, T14 summary cache, telemetry or network service.

Architecture: pure domain UsageBucket, UsageImportState, DailyUsageReport and UsageSyncer; Android-only integration:usage module wraps AppOps/UserManager/UsageStatsManager/PackageManager and WorkManager scheduling; core:data owns RoomUsageRepository using existing v1 tables; app wires worker and settings UI.

Use queryUsageStats(INTERVAL_DAILY), preserving actual platform first/last timestamps and totalTimeInForeground. Query bounds can expand to complete intervals; these are Android-reported daily buckets, grouped by their start date in the display zone, never prorated to imply exact local-day measurements. App totals are not device screen-on time and simultaneous apps may overlap. Empty/unavailable data is not a measured zero.

Within an unchanged native clock epoch, retry identity is package + native bucket start, independent of growing end/duration. Native identity is not globally immutable: Android can rewrite historical timestamps after a wall-clock correction. Persist the initial wall/elapsedRealtime/BOOT_COUNT anchor, compare cumulative drift over one second and reboot identity before/after queries, and quarantine history on discontinuity. A durable minimum native start at detection time excludes old reporting intervals; only newly started intervals import thereafter. Keep this boundary across opt-out and enforce it again in Room. Reboot/correction can leave the affected interval permanently incomplete, which Settings explains. A same-package/different-start overlap guard remains an additional defense. Unreadable clock/boot identity fails safely. Imports update the original envelope/child IDs and preserve unrelated metadata/links. Data and checkpoint commit atomically. First import reads seven days; later imports start two days before the checkpoint, bounded to seven days, allowing rolling/late buckets to update. Empty/error/permission changes retain records and the last successful checkpoint.

Opt-in persists in integration_state checkpoint JSON, with existing enum status projection. Permission is checked on foreground return and before/after each query. Disable prevents further writes and cancels scheduled work. WorkManager performs unique six-hour periodic work; transient failures/locked device get bounded retries, revoked access stops work. Explicit Import now supports immediate refresh.

Settings explains access and on-device storage before opening native settings, handles absent settings activities, distinguishes disabled/access required/locked/unavailable/no data/error/ready/changed intervals, shows last successful import and stored daily totals with app label and package fallback. Timeline/Today/detail reuse labels. No QUERY_ALL_PACKAGES; launcher intent visibility only.

Constraints: API28/35, AGP8.7.3, Kotlin2.2.10, Room2.8.5, JDK17. WorkManager2.10.0 is cached and compiled for API35. Preserve SDKs/schema/pre-existing untracked files. Work in shared checkout; no commits or emulator execution, following prior task convention.

Alternatives considered: event reconstruction offers fine intervals but depends on short-lived transition history and missing boundary state; aggregate usage preserves platform totals directly. Treating requested query bounds as bucket bounds mislabels expanded intervals; retain returned native bounds instead.
