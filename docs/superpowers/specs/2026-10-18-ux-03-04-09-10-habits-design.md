## Intent and approach

Make logging/correction easier without changing the habit model. Reuse compact rows, typed pickers and repository rules. A rewrite risks retry/undo and future-effective schedules; copy alone leaves raw correction inputs and inactive rows dominant.

## UX-03: Typed correction and precise round trips

Replace String fields in HabitLogCorrectionDraft with: logId: UUID, originalDate: LocalDate, originalOccurredAt: Instant?, zone: ZoneId, selectedDate: LocalDate, selectedTime: LocalTime?, timeChanged: Boolean. Initial selectedTime retains original seconds/nanos; display minutes only.

hasChanges compares date and effective full selected time against originals. Picker cancel and choosing the currently displayed hour/minute are no-ops preserving precision. A different minute sets seconds/nanos to zero. Returning after a real edit to a minute with different precise seconds stays dirty. Date-only edits preserve precise local time. “No time” selects null; date-only logs begin null.

Save original/selected fields and zone as primitive ISO/epoch values in SavedStateHandle. Restore dirty comparison after recreation. Hydrate older string drafts using original log metadata; if impossible, show missing-log feedback rather than invent a clean baseline.

Use DatePicker/TimeInput honoring UX-16 and explicit No time; no raw ISO labels. Validate using habitLogTime; preserve original valid overlap offset, otherwise existing first-valid-offset policy. Reject gaps/future instants. Typed errors DATE, TIME, SAVE, MISSING: date errors on Date, gap/future-time errors on Time; persistence failures retain draft with Retry.

Untouched Save closes without writing. Changed save retains id, recordedAt and zone. Prevent duplicate Save while busy. Cancel/outside-tap/Back use one path: clean closes once; dirty asks Discard/Keep editing. Picker Back closes picker first. Closing correction stays on detail; a later Back navigates away. Busy save blocks dismissal until its result.

## UX-04: Detail hierarchy

Order: selected date/progress → Log and secondary Skip/Resume today → pending saves/retry/undo/errors → history → Schedule details → Manage habit disclosure. Errors stay beside their action.

Schedule details show current target/days/zone and actual future-effective date plus existing Cancel pending behavior. Manage habit contains Edit, Pause/Resume, Archive, Delete with current eligibility. Delete remains destructive with confirmation; retain other existing confirmation policies. Never resume an archived future-start schedule. Manage habit is a visible labeled ≥48 dp disclosure, saveable by habit ID.

## UX-09: Compact rows/setup

Content/open target: wrapping name → “1 of 10” → secondary unit/state. Separate trailing “+1”, with accessible label naming habit/unit. No clickable parent swallowing the child; both ≥48 dp. At narrow width/large text, put +1 on another row.

Progress fraction clamps count/target to 0..1; display exact count above target. Only show progress when reviewTarget() is nonnull. Keep pending failure/retry/undo/skip/effective-date feedback. Reuse visuals in TodayHabitsCard without changing UX-01 ordering/preview or UX-02 count scope.

Editor copy: “What are you counting?”, “For example, glasses or pages”, “Each tap adds one.” Unit repetitions only; no arbitrary amounts/duration mode. Preserve name 100 code points, unit 30, target 1..999, required weekdays and start-date rules.

Presets: Daily = seven days; Weekdays (Mon–Fri) = Monday–Friday explicitly in all locales; Custom preserves selection and exposes individual days. Individual changes rederive preset. All presets leave individual days available and call existing setWeekdays; no persisted preset field.

Tracking-zone explanation moves behind disclosure after setup; device/tracking-zone mismatch with affected date stays visible. Tracking zone stays fixed.

## UX-10: Scheduled/other groups

Partition by day.reviewTarget() != null, not canLog: future scheduled dates, skipped and completed days stay Scheduled. Other habits includes off-day, not-yet-started, paused/archived rows returned by repository; do not remove their history.

Always show Scheduled for this day. If empty: “No habits scheduled for this day” and Today using the existing tracking-day callback (omit redundant Today when already on that date). Then collapsed “Other habits (N)” with state/open targets, no disabled logging button/repeated explanation. Force expansion if a hidden row has pending/failed log so Retry stays reachable. Persist expansion per selected date. Domain logging eligibility remains row.canLog.
